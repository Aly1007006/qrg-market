# QRG MARKET — UI COMPLETION & FUNCTIONAL REGRESSION

Дата: 3 октября 2026 года.

## Сделано

Сайт приблизили к завершённому продукту без перестройки backend и без подмены реальных банковских операций. Сохранены светлая витрина, fashion-hero, графитовые поверхности и песочный акцент из предоставленного референса.

### Публичный интерфейс

- Реализовано избранное товаров и бутиков без регистрации: кнопки-сердечки, счётчик в header, отдельная страница `/favorites`, удаление и сохранение после перезагрузки браузера.
- В избранном хранятся только тип и slug предложения. Цена, фотографии и контакты читаются заново из публичного источника. Недоступный товар или скрытый магазин не возвращается через обход публичного API.
- Избранное ограничено 24 позициями, по 8 на странице. Демо и настоящие предложения используют разные ключи хранения. При запрете localStorage работает временное сохранение в текущей вкладке с доступным уведомлением.
- Добавлена отдельная публичная страница `/shops` с ограниченной пагинацией и карточками активных бутиков. Ссылки «Смотреть все» и «Бутики города» теперь ведут к магазинам, а не к каталогу товаров.
- Добавлена галерея товара: основная фотография, миниатюры при нескольких фото, увеличение, переключение, клавиатурное управление и закрытие с возвратом фокуса.
- В каталоге добавлены компактные выбранные фильтры. Удаление одного фильтра сохраняет остальные параметры и сбрасывает страницу пагинации. Удаление категории также снимает зависимую подкатегорию.
- Улучшены карточки, состояния избранного, отметки реальных скидок и новинок, хлебные крошки и плотность интерфейса.
- Исправлена мобильная шапка: избранное, вход и меню помещаются в одну строку; поиск остаётся отдельной удобной строкой.
- Исправлена ширина сохранённой карточки бутика на mobile.
- Мобильный drawer закрывается после выбора ссылки и по фону. Поиск, каталог, ссылки на товары и бутики сохранены.

### Кабинет продавца

- Приведены к общей визуальной системе список магазинов, sidebar, активная навигация, формы, поля описания, списки товаров и блоки фотографий.
- Статусы магазинов в основных разделах показаны понятными русскими подписями.
- Улучшены onboarding, индикатор готовности и checklist реальных шагов настройки магазина. Процент берётся из существующих данных, а не придумывается интерфейсом.
- Сохранены существующие проверки ролей, CSRF, endpoint allowlist, отправка форм и загрузка изображений.
- Исправлен найденный при браузерной проверке дефект: горизонтальная навигация больше не растягивает мобильную CSS-grid страницу до ширины всех ссылок.
- В отдельном тестовом магазине выполнены вход, открытие списка товаров, просмотр фотографии из настоящего локального S3, редактирование названия и проверка сохранённого значения после перезагрузки.

## Database

Database: изменений нет.

Новые миграции, таблицы и индексы в рамках этого прохода не создавались. Существующие миграции прогнаны тестами в отдельной одноразовой PostgreSQL с PostGIS и pg_trgm. Пользовательская local database и её volumes не использовались для regression-тестов и не очищались.

## Security

- Проверены границы избранного: повреждённый JSON, неверные типы, небезопасные slug, дубликаты и ограничение размера.
- Сохранённые ссылки не являются разрешением доступа: сервер использует только действующие публичные endpoints.
- `/favorites` не индексируется. Демо-данные не становятся production source of truth.
- Не добавлены аккаунты покупателей, buyer payments, кошельки продавцов, escrow или сбор дополнительной PII.
- Перепроверены IDOR/BOLA, изменение shop/member/variant IDs, массовое назначение ролей, отзыв membership и CSRF.
- Перепроверены реальные декодирование и S3 round trip изображений, вредоносные MIME, лимит 10 MB, лимит 10 фото, concurrent upload reservations, повторная отправка и orphan cleanup.
- Перепроверены гостевые заявки, consent, anti-spam, rate limits, повторные отправки и tenant isolation.
- Перепроверены admin MFA, изоляция admin/seller sessions, неизменяемый audit trail и критические permissions.
- Перепроверены подписки и payment security только с offline test fixtures: неверные суммы, валюта, merchant, callback replay, повторный payment ID и fake success redirect.
- Реальная банковская транзакция, изменение production credentials и внешнее развёртывание не выполнялись.

### Ошибки, найденные при проверках

1. Новый SSR-тест удаления фильтра первоначально зависел от порядка HTML-атрибутов. Исправлен selector: нужная ссылка определяется по доступному имени, затем отдельно проверяется её URL. Проверки сохранения поиска и удаления цвета/страницы не отключались.
2. Отдельному тестовому S3 первоначально не был передан `S3_FORCE_PATH_STYLE=true`. Исправлена конфигурация запуска. После неудачной попытки остались одноразовые intents, влияющие на глобальный cleanup count; собственные тестовые DB/storage пересозданы и вся регрессия успешно пройдена на чистом окружении. Production storage code не подменялся.
3. Source-integrity не может запускаться в build image без Git и `.git`. Он выполнен в настоящем host repository и прошёл. Это не ошибка исходного кода.
4. Мобильная сетка кабинета растягивалась содержимым sidebar. Исправлена через ограниченную grid track и `min-width: 0`; добавлен regression-тест. После исправления document scroll width равен client width.

## Известные проблемы

1. Production launch по-прежнему не разрешён: реальные Halyk merchant/verification contract, доставка password reset, KZ deployment/TLS/IAM, alerts, privacy residency evidence, backup/restore и image CVE evidence требуют внешней настройки. Полный перечень — в `docs/recovery-audit-report.md`, EXT-001…EXT-010.
2. Предпросмотр публичного дизайна на `http://localhost:43182` использует явно помеченные development fixtures. Отправка заявок и реальных сообщений из демо-карточек намеренно недоступна. Рабочие реальные API/BFF flows проверены отдельно в изолированной базе.
3. Guest favorites сохраняются только в браузере текущего устройства, не синхронизируются с аккаунтом или другими устройствами. Ограничение явно показано в интерфейсе.
4. Полный assistive-technology audit и production-scale performance acceptance ещё не выполнены.

## Технический долг

Новые инфраструктурные компоненты, packages и зависимости не добавлялись. Новый сознательный tradeoff — device-local favorites с ограничением 24 references; серверная синхронизация не входит в этот проход. Это не обязательная регистрация покупателя и не скрытая зависимость публичного каталога от аккаунта.

## Следующая рекомендуемая фаза

Production-readiness closure: закрыть внешние gates EXT-001…EXT-010 фактическими credentials/configuration/acceptance artifacts, затем повторить production gate для reviewable commit и точных runtime image digests.

Внешний deployment, live payment, commit и push автоматически не выполнялись.

## Сохранность данных и локальный результат

Существующие изменения пользователя, local database/storage volumes и посторонние контейнеры сохранены. Собственные одноразовые QA аккаунты, магазины, тестовые фотографии и контейнеры удаляются после проверок. Публичный демонстрационный preview оставлен работающим только на loopback `127.0.0.1:43182`.

Итог: интерфейс и локальные рабочие сценарии заметно доведены; это не заявление о завершённом коммерческом production-запуске.
